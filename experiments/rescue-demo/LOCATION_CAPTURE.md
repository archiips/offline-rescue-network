# Optional native device observation

Implemented 2026-10-09. Public users can request a one-time Core Location observation, remove it, edit a manually reported place/floor, and review before sending. New drafts default to Unknown floor. Capture itself never sends. Both audiences and original/correction history retain coordinates, reported horizontal accuracy, observation timestamp with time zone, approximate authorization and “not live.” Coordinates do not determine building or floor.

Core Location is a device observation, not a promise of GPS reception, indoor accuracy or availability without connectivity. Capture accepts finite valid coordinates/nonnegative accuracy with capture-time age −5…60 seconds. A captured draft can become older before send; its timestamp remains explicit and it is never silently refreshed. Permission failure leaves manual sending available. Manager identity fences stale callbacks; 30-second timeout, background/view/setup/mode/role changes cancel outstanding capture. Permission-prompt inactivity alone must not cancel it.

Location reports use `ORLOC1:` JSON inside the bounded existing C++ location field. No ORX1/SQLite migration; legacy reports remain readable. Malformed tagged reports show unavailable. Matched clients are required for structured presentation. The same secure envelopes protect transport; local SQLite history remains unencrypted, disclosed before capture. Do not use this checkpoint as private-data or operational authorization.
