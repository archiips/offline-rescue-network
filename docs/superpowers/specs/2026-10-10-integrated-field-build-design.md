# Integrated field-test software design

## Outcome and authorization
One rescue application retains public iPhone and responder iPad journeys. User requested completing remaining software before a combined physical test, under existing continuous build/delegation/publication authorization. No routine approval gates are added. This is a testable prototype, not verified UW enrollment, automatic dispatch, physical accuracy or universal mesh reach.

## Existing capability and gaps
Prepared registered direct foreground exchange and 16-public inbox exist. Apple logical-floor and calibrated relative-altitude research, permitted connected Wi-Fi capture, encrypted original phone-observation exchange and C++ uncertainty graph exist. Native relay custody is manually controlled, single pair, single relay. A local Keychain registrar issues synthetic profiles. Preserve all existing histories, modes, manual reports and separate receipt/acknowledgment/handling.

## Localization milestone
Add a bounded device-local survey map with explicit campus/building context, observed handset floor coverage intervals (not AP installation floors), dated provenance and expiry. Exact BSSID match and fresh observation are mandatory. Same SSID supplies no campus/floor inference. Conflicting entries are rejected; multi-floor coverage returns an interval/Unknown. Local map values never enter peer/SOS payloads. The graph accepts a local surveyed interval without converting derived estimates into original sensor readings. Native preparation imports a map and selects context; capture automatically recomputes graph. Keep missing permission/entitlement/map Unknown; free-account build remains usable without Wi-Fi capture. Integrate a separately dated estimated-floor summary into reviewed SOS without replacing reported floor in a later checkpoint.

## Relay milestone
First automate the existing prepared-pair foreground relay using discovery only as routing hints, signed destination receipts as authority, exact durable encrypted retries and cancellation fences. C++ must select only eligible discoverable destination flows before consuming attempts, so missing phones do not exhaust retries. Preserve manual diagnostics. This is one relay until a separately verified multi-hop protocol exists.

Registered delayed first contact requires credential-bearing encrypted application admission independent of the 10-second interactive handshake. Prepare a verified responder directory before an outage; a sender cannot encrypt a private request to an unknown key. Never extend handshake leases or adopt a key from a Bonjour name. Carry issuer/realm/role/time/revocation checks and per-conversation registry fences through asynchronous work. This is a separate security checkpoint, not a timer on the current direct worker.

## Enrollment milestone
Build an organizer-controlled preparation service around existing issuer/profile validation, with explicit responder approval and device-key possession. Public registration is not self-assigned responder authority. Do not claim UW account integration without UW authorization or credentials. No deployment, account/security changes or third-party data transfer are implied. Local synthetic service can exercise the complete preparation contract; an actual organization's authoritative integration remains an external prerequisite.

## Alternatives and critique
Reject arbitrary SSID→floor guesses, contact→same-floor edges, new learned classifiers without labels, tapping/NFC, purchased beacons and emergency-time pairing. Reject weakening signature/canonical checks and short-lived handshake freshness for delayed relays. Keep pure inference/workflow/queue ownership C++; Swift adapts native inputs/security/transport. Imported local surveys are user-supplied research references, not independently authenticated campus truth. Tests must include cross-floor coverage, expiry, wrong contexts and contradictions, not only successful single-floor samples.

## Definition of done
Each checkpoint has fresh behavioral tests, native build/rendered interaction where feasible, scoped independent review, privacy/staged diff inspection and durable evidence. Combined physical protocol covers prepared registration, automatic foreground SOS/receipt/ack/reply, no-WAN and no-shared-AP separately, delayed relay with three devices, sensor ground truth at home/Bothell/Seattle. Missing physical hardware, real campus maps/authority and entitlement remain explicit test prerequisites, never fabricated results.

## Registered delayed-contact protocol ruling — October 11

Keep the existing 4276-byte relay frame/queue payload limit and 16 custody rows. ORRG1 wraps unchanged ORL1 with two signed public role credentials; verify issuer, realm, role, revocation snapshot, time, full cards and inner sender signature at every admission/forward. A public profile may include up to four issuer-signed responder credentials; deterministic directory selection precedes cache creation. Discovery hints confer no authority. No direct ten-second proof lease is extended.

The responder preflights the first decrypted event through C++, journals admission, commits the bound conversation and finalizes its registry before producing an encrypted relay receipt. At most four provisional contexts and sixteen admitted/journaled conversations remain. Peer credentials are public bounded registry metadata; each conversation owns separate inner/outer caches. The outer retry cache signs the complete wrapper using its owner key, checks row metadata and zero attempts, and binds its guard to full-card digests. Its additional 64-byte signature means locally cached wrappers must fit 4212 bytes; oversized content fails explicitly rather than widening storage limits. Original credentials/bytes remain unchanged across retries; expired credentials fail closed.

Relay custody persists exact wrappers. Two directional public-card routes per prepared pair are saved before custody; metadata grants no authorization. Before C++ consumes an attempt, a fresh nonce-bound signed readiness probe proves destination key possession. A valid acceptance is correlated with the exact inner packet. Its reverse receipt is admitted durably before removing the forward item. Registered network workers use a separate Bonjour service, bounded candidates/batches and pre/post-await generation fences. Stop/background stops all contacts; custody never confirms the public outbox. Duplicate exact forward copies can remain after the original receipt returns and drain on a later contact or expire.

Organizer network preparation uses fresh signed challenge/device proof, explicit organizer issuer approval, four approved responder cards maximum and nested canonical signed profiles to keep frames within 4096 bytes. Issuer secrets stay in the registrar. Authorization remains synthetic and serial-based: remove a card from the organizer allowlist to prevent newly issued credentials for that key; already-offline revocation snapshots cannot refresh themselves.

Review revisions: bound malformed relay candidates; reject a different authorized responder before opening a selected-peer cache; sign the entire outer wrapper to prevent equivalent-credential substitution from changing retry bytes; authenticate destination readiness before spending attempts. Independently test each boundary. Native public requests keep manually reported place/floor separate from dated estimated floor; local AP identifiers never enter SOS or peer observations.
