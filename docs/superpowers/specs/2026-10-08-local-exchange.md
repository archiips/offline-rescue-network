# Local sample exchange between independent endpoints

One portfolio rescue project, public iPhone and responder iPad, C++ engine and SwiftUI. User authorized continued implementation and reviewed public checkpoints; inline execution with read-only Claude review continues. Physical testing is unavailable. Goal: actual local socket exchange of sample SOS, durable device receipt, explicit acknowledgment, reply and updates between separate processes with separate databases. Preserve every existing training-mode journey and saved session.

## Design and alternatives

Add a local-exchange mode alongside the existing simulated training mode. Each local endpoint owns one Model and one SQLite outbox; no shared database or remote-model access. Public/command fixture roles, one training exercise/request and synthetic presets remain. A version-2 role-tagged store reuses bounded SQLite transaction code without migrating the existing version-1 simulated session. Reopen validates acceptance order, receipt and outbox consistency. Role changes open another store and stop transport first.

Use NWListener/NWBrowser/NWConnection with Bonjour `_rescue-demo._tcp` and includePeerToPeer. Both endpoints advertise and can select an unverified opposite-role peer. One bounded event per TCP request, one receipt response, then close. C++ owns a strict binary event codec (ORX1, big-endian integers and length-prefixed strings), bounded to 4096 bytes. A 4-byte big-endian length frames the stream. Invalid/incomplete/oversized packets fail without state changes. No external packages.

For inbound non-receipt events, stage Model acceptance and a deterministic receipt together, commit before responding. Receipt packets are derived from committed history and returned again on duplicate original requests; they do not require an independently transmitted receipt queue or receipt acknowledgment loops. Sender persists the returned receipt and removal of the matching original outbox event in one transaction. A lost response leaves the sender’s original queued; retry returns the same receiver receipt. Receiving a human acknowledgment is separate from device receipt. Each outgoing acknowledgment/reply has its own receipt. Reserve one history slot for every pending original’s future receipt; new local/inbound events cannot spend that reserve. Validate increasing outbox sequences on reopen. Full store, save failure, absent dependency, stale instance or network failure retains unconfirmed transfers.

Rejected: networking the existing two-model simulation would fake endpoint ownership; adopting the fixed-frame probe would discard actual rescue workflows; implementing encryption, relays, AI or multiple requests now expands beyond locally verifiable direct exchange. This remains plain, unauthenticated synthetic networking, not the private product protocol. Bonjour names/fixture roles cannot establish responder authority.

## Bounds and lifecycle

Model 128 events, outbox 64 non-receipt events, IDs 64 bytes with canonical fixture author/sequence and receipt reference forms, valid UTF-8 strings, combined text/location 2 KiB, sequences/revisions <=4096. Store main file 4 MiB and sidecars 8 MiB each; inherited schema/generation/locking/recovery checks. Network session cap 8, discovery cap 20, absolute deadline 8 seconds, one client batch at a time with max64 events. MainActor owns Swift network/controller state. Stop invalidates callbacks, cancels sessions and discovery, retaining saved outboxes. Background stops networking; foreground restart and retry are explicit. No silent delivery on store reopen. No persisted transient transport status.

## Native UI and verification

Existing training mode remains default, with its separate saved database. Local mode selects one role, starts/stops exchange, lists discovered peers and transfers pending messages to the selected peer. Reuse PublicView/ResponderView and their SOS review, explicit acknowledgment, per-message delivery, correction, withdrawal, assignment/resolution, late review and explicit reopen. Local reset only clears the selected endpoint; both participants must coordinate reset, because fixed exercise IDs have no new epoch. No text input for personal data. Show sample/local exchange context and storage/network failures.

C++ tests cover independent stores, dropped receipt/retry, reopen, invalid/mismatched packets, receipt atomicity, role/store isolation, full capacity and save locks. Swift tests cover framing, controller and actual loopback NW sockets with two independent stores. Add a Mac CLI host/client harness for reproducible separate-process evidence, then native simulator-to-Mac workflow/restart and rendered checks. Retain the 24 CTest / 10 Swift baseline and run sanitizer, Release and simulator builds. NET-01/SEC-01/ENG-04/M1 remain open; physical no-AP, local permission denial, hardware/OS compatibility, background radio and power-loss guarantees are unproven.

## Research / critique

Sources accessed 2026-10-08: [Apple includePeerToPeer](https://developer.apple.com/documentation/network/nwparameters/includepeertopeer) enables available link technologies, not a route guarantee; [TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) requires Bonjour/local network plist descriptions and states simulator privacy is unsupported; [NWConnection receive](https://developer.apple.com/documentation/network/nwconnection/receive(minimumincompletelength:maximumlength:completion:)) describes bounded stream reads. Existing probe and storage evidence informs code reuse; this design and its limits are engineering judgments.

Correctness: receiver event/receipt and sender receipt/outbox removal each commit independently; dropped replies must be demonstrably retryable. Simplicity: receipt regeneration avoids receipt-ack loops. Privacy: preset data and explicit local-only experiment, no authenticated identity claim. Maintainability: C++ codec/endpoint, SQLite store, Swift transport and controller each have one owner. Testing: socket tests supplement independent-process/native checks; no simulated route inference. UX: preserve training, reuse complete role workflows, keep failed startup unavailable and warn that reset requires coordination. Fixed exercise IDs and synchronous small writes are deliberate bounded-demo limits.
