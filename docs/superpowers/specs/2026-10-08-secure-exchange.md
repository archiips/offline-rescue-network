# Secure local synthetic exchange

One portfolio app retains public iPhone/responder iPad workflows and the C++ engine. Deliver attended two-endpoint pairing, encrypted signed requests and receipts, persistent keys/trust, restart/retry and fail-closed packet handling. Training and explicit plain diagnostic host remain available. No personal data, agency credential, cloud enrollment, relay, background guarantee or sales readiness follows.

## Decision and evidence

Apple CryptoKit HPKE (RFC 9180 base mode, X25519/SHA256/ChaChaPoly) plus a distinct Ed25519 signing key is the bounded Apple-only adapter. This supersedes the draft's C++ crypto preference for this checkpoint only: native supported primitives avoid a vendored cross-platform crypto build before proving the workflow. C++ retains parsing, role/action authority, SQLite transactions and projections. A portable crypto adapter remains later work. libsodium would fit portable C++ but adds a pinned source/cross-platform build; TLS alone doesn't retain endpoint-private relay envelopes. A shared secret alone permits role impersonation by its holder.

Sources checked 2026-10-08: [Apple HPKE](https://developer.apple.com/documentation/cryptokit/hpke), [ciphersuite](https://developer.apple.com/documentation/cryptokit/hpke/ciphersuite), [RFC9180](https://www.rfc-editor.org/rfc/rfc9180.html), [Keychain accessibility](https://developer.apple.com/documentation/security/ksecattraccessiblewhenunlockedthisdeviceonly). HPKE is supported from iOS17/macOS14; our existing package minimum iOS18/macOS14 is retained. No physical compatibility inferred.

## Pairing and authority

Each selected role has random signing/encryption private keys and UUID epoch in a Keychain record. Public card ORP1 is exactly85 bytes: magic4, role1 (0/1), UUID epoch16, signing public32, X25519 public32. Its SHA256 fingerprint covers all85 bytes. An operator exchanges cards out of band, compares the full fingerprint on the actual other endpoint and explicitly imports the opposite role. No discovery-name trust, automatic enrollment or private-key export. Importing a card asserts attended sample authority, not verified firefighter identity. A pinned peer cannot change until a new session. Duplicate identical import is harmless.

Each session uses an isolated UUID-named v2 SQLite file beneath secure-role storage. Reset rotates keys/epoch and clears trust by saving a new Keychain record before opening the new store; old ciphertext is rejected and both endpoints must re-pair. Prior sample databases remain on disk (retention/encrypted storage still open). Missing keys with existing secure databases, or a paired record with missing epoch database, fails closed rather than silently reusing or replacing history. Packet/reopen paths check both current record and expected history. Explicit new-session recovery rotates keys, clears trust and preserves earlier sample files; it still refuses failed Keychain reads. Failed Keychain reads/writes are errors. Tests inject a record store; real paths use Keychain only: iOS is non-synchronizing WhenUnlockedThisDeviceOnly with a stable app-scoped namespace; unsigned Mac diagnostics deliberately use login Keychain, which does not enforce that accessibility class, without claiming Secure Enclave protection.

## Envelope and retry

ORS1 is magic4 + sender-card SHA25632 + recipient-card SHA25632 + HPKE encapsulated key32 + ciphertext (plaintext1..4096 plus16-byte tag) + Ed25519 signature64. Total181..4276. Info is fixed domain `offline-rescue/ORS1/HPKE/base/X25519-SHA256-ChaChaPoly` plus first68 header bytes. AEAD additional data is the entire100-byte header. Signature is over domain `offline-rescue/ORS1/signature` plus header+ciphertext. Fresh HPKE Sender/Recipient context per packet (one seal/open per context). Exact version, size, sender/destination pins and signature are checked before decrypting; C++ then validates ORX1 IDs/kinds/author/role. Secure mode has no plaintext fallback.

Identical same-epoch authenticated retry is intentionally allowed: C++ dedupe returns the already committed receipt without new history. Re-sealing a retry changes ciphertext but not domain event. Old epochs, other peers, reflected own packets, tampering and plain packets reject before trusted-state mutation. No forward-secrecy claim against later recipient-key compromise. Body confidentiality does not hide traffic size/timing or hashed endpoint identities.

## Transport and UI

Secure discovery uses `_rescue-sec._tcp`, separate from `_rescue-demo._tcp`. Parameterize the existing bounded frame/transport with a hard permitted cap of4276; plain defaults stay4096 and tests stay strict. Native Local exchange selects secure endpoints and presents pairing in a sheet so existing rescue content remains usable on phone/iPad. Start/transfer require a paired peer, snapshots still display delivery, explicit human acknowledgment and handling separately. Role/session switch stops and invalidates networking; background and restart stay stopped. Key/pair errors remain visible and cannot route actions into training by accident.

## Acceptance and critique

Verify fresh runtime-generated keys, opposite-role cards, packet corruption, foreign/destination/epoch rejection, exact duplicate retry, restart continuity, dropped response, Keychain failure/key loss, reset rotation, bounds and real Network sockets. Retain all original suites and native training/local workflows. Inspect rendered pairing and both audiences; build native simulator and demonstrate encrypted simulator-to-Mac exchange with preset data. Review with authorized Claude Opus 5.5 medium, no model fallback.

Critique: signed base-mode HPKE avoids a homemade key schedule; canonical fixed-width headers remove JSON signing ambiguity. A role switch could accidentally mutate training: guard local mode even if secure initialization fails. Reset could let old ciphertext re-enter fixed request IDs: rotate identity/epoch and isolate databases. Concurrent old tasks could confirm into a new profile: stop/generation guards and capture the same endpoint. Key loss must not regenerate behind the user's back. Pairing adds UI height: sheet with full selectable fingerprint and explicit trust action. Limits remain bounded before expensive crypto. This is not an independent protocol audit or completion of SEC-01/ENG-05.

## Evidence-driven revisions

Nearest-existing-ancestor path canonicalization keeps Mac namespaces stable when a missing folder is created; iOS uses stable logical app identity across container moves. Simulator Keychain needs signing: app-target-only simulator entitlements and Xcode ad-hoc signing are configured.
